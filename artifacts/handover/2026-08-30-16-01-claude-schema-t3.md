## 작업 환경 (세션 초반)

- 이 환경엔 pnpm 미설치. 전역 `corepack enable`은 `C:\Program Files\nodejs` 쓰기 권한 없어 실패.
- 해결: `corepack enable --install-directory ./.corepack pnpm` 로 프로젝트 로컬 shim 생성 (`.corepack/`, 이미 `.gitignore` 제외됨). pnpm 9.15.4 동작 확인.
- 실행 방법: `corepack pnpm <cmd>` (PATH 불필요) 또는 `.corepack`을 PATH에 추가.
- `pnpm install` 성공. 커밋된 `pnpm-lock.yaml` 기준.
- **steiger lint 깨짐 수정**: lockfile이 `steiger@0.5.13` + 중첩 `@feature-sliced/steiger-plugin@0.6.0`을 물었고, 이게 `web-tree-sitter@0.26`을 써서 Node 20.14.0에서 크래시(`bad export type for 'deleter'`). `package.json`에서 `steiger`를 `0.5.12`, `@feature-sliced/steiger-plugin`을 `0.5.8`로 고정 → steiger 정상 실행.
- 미해결: 루트에 stray `package-lock.json`(npm install 흔적) 존재. 삭제 여부 사용자 확인 대기.
- 미해결: `pnpm lint`(steiger)는 빈 슬라이스(`src/entities`, `src/features`, `src/widgets` = `.gitkeep`만) 때문에 `fsd/insignificant-slice` 3건으로 exit 1. T2~T6에서 채워지면 해소. T3과 무관.

## T3 결정 사항 (사용자 확정)

1. 공고→분석 흐름: 클라이언트가 `job_postings` INSERT → Route Handler 호출 → 서버가 DART 조회 + `companies` upsert + AI 종합 + `company_analyses` INSERT.
2. `companies`: 전체 공유, 기업당 1행, `corp_code`(DART 8자리) UNIQUE, 쓰기는 service-role만.
3. `company_analyses` 키: `(user_id, company_id, role)` 이력 누적(덮어쓰기 없음). 해당 (회사,직무)에 기존 분석 있으면 재사용, 없으면 새로 실행. "다시 분석하기"는 항상 새 행.
4. `job_postings` 중복 판정: 같은 (회사 + 직무 + 고용형태 + 게시일 posted_at) 이면 중복. 사용자별.
5. `company_analyses` 쓰기: 로그인 사용자 본인 행 INSERT 허용. UPDATE/DELETE 불가(불변). SELECT 본인만.
6. `profiles`: `auth.users` INSERT 트리거(security definer)로 자동 생성.
7. 도구: SQL 마이그레이션 파일 + `Database` 타입 수기. Supabase CLI 도입 안 함.

## 생성/수정 파일

- `supabase/migrations/20260830155347_init.sql` — 4개 테이블 + 트리거 + RLS 전체
  - `moddatetime` 확장으로 updated_at 자동 갱신
  - `job_postings`: `company_key`, `role_norm` = generated stored 컬럼. `unique nulls not distinct (user_id, company_key, role_norm, employment_type, posted_at)` (Postgres 15+ 필요)
  - `company_analyses.company_id` = `on delete restrict` (이력 보호), `job_posting_id` = `on delete set null`
  - RLS: `profiles` 본인 select/update / `companies` authenticated select만 / `job_postings` 본인 all / `company_analyses` 본인 select+insert
  - `create ... if not exists` / `drop policy if exists` 로 재실행 안전
- `supabase/README.md` — 실행 절차, PG 버전 주의, 타입 수기 동기화
- `server/supabase/types.ts` — `Database` 타입 원본(수기). 마이그레이션 바뀌면 여기도 수동 갱신
- `src/shared/api/supabase/types.ts` — `export type { Database, Json } from "@server/supabase/types"` 재노출
- `src/shared/api/supabase/{client,server,middleware}.ts` — `createXClient<Database>()` 제네릭 연결
- `server/supabase/admin.ts` — `createClient<Database>()` 연결
- `server/jobs/verify-schema.ts` — 스모크 테스트 스크립트 (레포 보관 여부 사용자 확인 대기)
