## 발견된 문제 (2건, 둘 다 실제 코드 확인해서 근본 원인까지 특정함)

### 1. 캘린더 이벤트가 점(dot)이 아니라 행 전체를 채우는 파란 막대로 렌더링됨 [blocker급]

- **증상**: 이벤트(북마크 공고 마감일)가 있는 주(週)에서, 의도한 7px 점 대신 그 주 전체 너비를
  채우는 굵은 파란 막대가 나타남. 이벤트 없는 주는 정상.
- **원인**: `react-big-calendar`의 기본 CSS(`node_modules/react-big-calendar/lib/css/react-big-calendar.css`)가
  `.rbc-event { background-color: #3174ad; ... }`를 정의하는데, `src/app/globals.css`의 오버라이드
  (`.rbc-event { background: transparent; ... }`)와 **동일한 클래스 셀렉터라 특정도(specificity)가
  같고**, Next.js 번들링 순서상 RBC 기본 CSS가 우리 오버라이드보다 나중에 로드되어 이겨버림
  (`calendar-view.tsx`에서 `import "react-big-calendar/lib/css/react-big-calendar.css"`를 컴포넌트
  파일에서 직접 import하는 구조).
- **재현**: `/dashboard/calendar` 접속, 북마크된 공고 마감일이 있는 달로 이동.
- **수정 방향(제안)**: `globals.css`의 `.rbc-event` 관련 규칙에 `!important` 추가해서 로드 순서와
  무관하게 항상 이기도록 하거나, RBC CSS를 더 이른 시점(예: 루트 레이아웃)에서 import해서 순서를
  뒤집는 방법도 있음 — 다만 `!important`가 더 간단하고 안전(서드파티 CSS와 싸우는 전형적 상황).

### 2. 다크모드가 앱 전체에서 전혀 작동하지 않음 [설계 공백, blocker급]

- **증상**: Playwright `colorScheme: 'dark'`로 렌더링해도 모든 페이지가 라이트 모드와 픽셀 단위로
  동일하게 나옴 — 캘린더만이 아니라 대시보드 등 전역 현상.
- **원인**: `panda.config.ts`에 `conditions: { dark: ".dark &" }`로 설정돼 있음 — 즉 다크모드는
  **`.dark` 클래스가 조상 엘리먼트에 있을 때만** 활성화되는 클래스 기반 방식인데, 코드베이스
  어디에도 이 클래스를 붙이는 로직(시스템 설정 감지 스크립트, 수동 토글 버튼, `next-themes` 등)이
  **없음**. `data-theme`/`ThemeProvider`/`next-themes` 검색 결과 전무.
- **의미**: `prefers-color-scheme: dark`인 사용자 브라우저에서 접속해도 다크 테마가 절대 안 뜬다.
  이건 파운데이션 단계(`redesign: design-system`)부터 있었던 공백인데, 그 단계 code-review가
  "완료(diff 직접 확인)"로 통과됐음에도 발견되지 못했다 — 정적 diff 리뷰만으로는 "런타임에 그
  클래스를 누가 붙이는가"가 코드에 없다는 사실이 눈에 잘 안 띄었던 것으로 보인다.
- **디자인 스펙 확인**: `artifacts/design/design-system.md`엔 "라이트 + 다크 둘 다"와 토큰 정의만
  있고, 활성화 방식(시스템 자동 감지 전용인지, 수동 토글이 있는지)은 명시돼 있지 않음 — 애초에
  스펙 공백이었을 가능성 높음.

## 사용자 결정 필요

다크모드를 어떻게 켤지 정해야 fix를 위임할 수 있다:
1. **시스템 설정 자동 감지만** — `prefers-color-scheme: dark`일 때 자동으로 `.dark` 클래스를
   붙이는 스크립트(루트 레이아웃에 인라인 스크립트, FOUC 방지) 추가. 수동 토글 UI 없음.
2. **수동 토글 스위처 추가** — 사이드바나 헤더에 라이트/다크/시스템 전환 버튼을 새로 만들고,
   `localStorage`에 선택 기억. 컴포넌트 하나 새로 만들어야 해서 스코프가 좀 더 큼.
3. 둘 다(기본은 시스템 감지, 수동으로 오버라이드 가능) — 가장 완전하지만 스코프 최대.
